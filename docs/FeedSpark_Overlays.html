How overlays are detected

The quick breakdown behind every figure on this page.
  1. Every feed scan reads the image field. The 4×-daily monitor (and ⚡ Scan live here) streams the feed and looks at each product's image_link and additional_image_link.
  2. Our images are unmistakable. A link served from dashboard.feedspark.com (or the lia. / feed5.com sibling hosts) is a FeedSpark-generated creative — the client's own CDN never appears there. That is what "overlay service on" looks like in the data.
  3. The URL string names the overlay. The engine path is the type (image_process_products_lifestyle.php = product × lifestyle split), the parameters are the recipe (img_url_left / img_url_right = the two source images, img_ver = the version, show_price / tag colours = a price tag, overlay_frame = the frame asset).
  4. The images are rendered live. Each example below is the actual overlay URL from the feed, loaded from our image service — so what you see is exactly the creative Meta or Google is serving.
  5. Coverage is tracked over time. Every scan stores the count per overlay type, so a drop (an overlay silently reverting to the plain product image after a URL rotation) shows in the trend before a client notices.
