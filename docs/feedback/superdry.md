## 2026-08-04 — round 3 (PPTX export)
- Ray attached `Superdry_FeedSpark_Strategy_Review_20242026.pptx`: "this is what I expected in the pptx downloads — study and transform export instruction as such."
  → Studied it. The gap was architectural, not cosmetic. His file is **template-driven**: a real theme (Inter, 6 scheme colours), a slide master, and **18 named layouts**, where every visual element — card panels, accent bars, decorative circles, gradient bar, wordmark — lives on the *layouts*, and the slides carry only text in placeholders (`<p:spPr/>` empty, bare `<a:r><a:t>`). Tables are native PowerPoint tables with a real `tableStyleId`. 50 slides, roughly one idea each.
  → `tools/deck_to_pptx.py` was doing the opposite: `add_shape`/`add_textbox` at absolute inch coordinates onto the **blank** layout (`slide_layouts[6]`), with font/size/colour hard-coded per run and tables drawn as rectangles. It rendered a convincing *picture* of a deck with nothing editable — no layouts, no placeholders, no theme, no native tables.
  → Rewrote it as a template populator. Kept the HTML parser (the good half — it already reads the deck's component vocabulary); replaced the whole renderer. Committed the stripped shell of Ray's file as `tools/templates/feedspark_deck.pptx` (41 KB, 0 slides, 18 layouts) — editing a layout there now re-themes every deck built from it.
  → **Fitting is layout, not shrinking.** PPTX doesn't clip an over-long text frame, it spills the text over the neighbouring card — so the failure mode is overlap, not truncation. First pass clipped text (destroying copy); corrected to shrink → then re-lay out (`pick_grid()` steps down to fewer, bigger panels; `balanced()` splits 4-at-3 as 2+2, not 3+1) → then trim one-line strips to their lead sentence. Nothing shrinks below 82%: the first working version hit 58% (~7pt) and "fits" was the wrong test.
  → Run size is set explicitly rather than trusting `normAutofit` — PowerPoint recomputes `fontScale` on open, LibreOffice and Google Slides don't, and a deck that only fits in one renderer isn't shippable. Size is the sole override; family and colour stay inherited so a global restyle still works.
  → Four bugs found and fixed by reading the generated output rather than trusting the run: the hero's long lede (a Google pull-quote) was being shrunk into the one-line subtitle strip — now gets its own Quote slide, matching Ray's reference exactly; sections without their own `.sec-title` rendered a bare " (cont.)" title — now inherit the chapter title; bar lists rendered with a fake `["", "Result"]` header, leaving an empty coloured band that reads as a bug — now headerless (`firstRow="0"`); and unfilled `Key Message` placeholders left a stray orange bar, since that panel is a layout shape.
  → Verified: Superdry 54 slides, Reiss 66, YuMOVE 49, template 46 — **0 over capacity, 0 empty placeholders, all 12 tables carrying the template style**. `--audit` is the gate.
