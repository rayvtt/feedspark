          Custom quotes

          Tracking field guide
          Tachyon task
          Which catalogue optimisation this brief delivers. Auto-detected from the brief's task title — override it if the scan guessed wrong. One optimisation per brief; bundles can't attribute hours cleanly and are excluded from averages.
          ASPL h
          ASPL hands-on setup hours (Muji's side): prompt & rule build, field mapping, sample generation, iteration until sign-off. Working time only — never waiting time.
          QC h
          London AM quality-control hours: sample reviews, brand-voice checks, feedback rounds until the output is approved.
          PM h
          Project-management hours: briefing, client comms, scheduling, chasing, status reporting for this brief.
          Mon h
          Ongoing monitoring hours per month after go-live: output QA, drift checks, exception handling. Monthly figure, not a running total.
          Bill units
          Billing tokens ÷ 1M — the unit AI processing is billed in, and the one token number shown per brief. Derived automatically, never entered. Hover a value for the actual + billing tokens behind it; click to edit them in the pop-up.
          Actual / billing tok (in the pop-up)
          Actual tokens = what the run consumed (input + output, from the Tachyon run log); ÷ products done it becomes the tok/product signal on the rate card (÷ volume done = tok/SKU, the variant view). Billing tokens = actual × the model's cost multiplier — what the provider actually charges for. Visual work carries a much higher multiplier than text (image tokens are dearer), so both are tracked, never just one.
          Run 1 req / 25 req (in the pop-up)
          AI running time end-to-end: one request at a time, and with 25 requests in parallel. Enter minutes — totalled per brand (shown as h m) in the summary below the table.
          Man time (ASPL h)
          The brand's total man time across its AI briefs, assigned to ASPL hours. The dev handback reports it per brand, so it lives on the per-brand summary row — splitting it per brief would be invented data.
          Vol done
          SKUs actually processed and delivered — what shipped, not what the brief hoped for. Variant-level count. Powers tok/SKU and the delivery record.
          Products done (in the pop-up)
          Parent products the run covered — unique g:item_group_id, the unit Tachyon is priced in (variants inherit). When a brief doesn't carry its own, the brand's product-group count from the dev handback stands in. Powers tok/product on the rate card.
          ＋ Add historic AI task
