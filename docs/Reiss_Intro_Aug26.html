The AI Landscape

Reiss shoppers don't only search anymore — they're using LLMs. Three pipelines decide whether Reiss is in the answer.

The shift

Search is shifting to AI answers

"What should I wear to a summer wedding?" — it might be answered from training data, a live web crawl, or the Merchant Center feed. The only way to win is rich, accurate, consistent product data across all three.

Zero-click is accelerating

AI overviews and agentic assistants resolve queries without a click. Reiss is either in that answer, or it doesn't exist for that shopper.

The model picks the product

LLMs read structured feeds, attributes and reviews. The FY25/26 live-feed audit read titles averaging 53 characters and 42% product-highlight coverage — the model gets less than the catalogue could give it.

Fashion is answer-shaped

Fit, occasion, fabric, size availability — every purchase decision is a question about a specific SKU in a specific size, and that's exactly what these surfaces answer.

Agentic commerce

Three protocols for agent-led shopping

Emerging open standards — they explain why the enrichment work in chapter 3 matters.

UCP — Universal Commerce Protocol

Google, Shopify, Target, Walmart

Common language for AI commerce
  • Agents handle discounts, loyalty, subscriptions
  • Checkout inside the AI conversation
  • Activated via native_commerce in Merchant Center
MCP — Model Context Protocol

Anthropic, adopted by Shopify

Real-time data access for AI assistants
  • Live inventory, pricing, order status via API
  • Relevant later, once stock-flag accuracy (chapter 6) is fixed
ACP — Agentic Commerce Protocol

OpenAI (powers ChatGPT Shopping)

Instant checkout inside ChatGPT
  • Integrates with Stripe, PayPal
  • Currently US-only for checkout; discovery is global

Chapter three

Spark AI Engine (Tachyon)

Intent generation, description enrichment, visual attribute harvest.

01

Feed extraction

Tachyon reads live Reiss product data — title, description, colour, material, size, price.

02

Intent generation

LLM generates 20–40 long-tail intent phrases per SKU from the real attributes already in the feed.

03

Scoring & validation

Terms scored against search-term reports; winners selected per SKU.

04

Feed injection

Winning terms embedded in title, description, product highlights — closing the product-highlight gap (the FY25/26 audit read 58% of SKUs with none).

Reiss example — Stanton Petite trousers

Input (real SKU from the export): Cream · Cotton · Petite · Size 4 · £58 sale

AI-generated intent terms:
"petite wide-leg trousers for short women"
"cream corduroy trousers office wear"
"cotton wide-leg trousers under £60"
"petite fit trousers 5ft 3in and under"
// 20-40 generated, top 4-6 used per SKU

Why this matters at 29-market scale

Manually writing intent-rich copy for ~20K SKUs across 29 markets isn't a resourcing question, it's a scaling question. Tachyon generates the long-tail language at catalogue scale from data that's already 100%-complete on the structural side (colour, material, size, product type, gender).

The title-fix precedent (chapter 8) already proved the AOT pipeline can touch every SKU — Tachyon extends the same reach to descriptions and highlights.

Chapter four

Tech Fit

Why the FeedSpark stack fits a 29-market fashion retailer — and where the fit isn't finished yet.

One stack, full catalogue

FeedHero + Tachyon run the same pipeline across all 60 feeds and 29 markets — proven on GB/DE/FR's 100% AOT title coverage, extending next to the 26 markets not yet audited.

Proven at scale

The same title-quality methodology behind the verified de-duplication fix already took GB from 39% to 0.1% duplicate titles — the fix works, the remaining task is reaching every market (chapter 8).

Golden Record discipline

99.9% attribute-completeness target — core structural fields read 100% in the FY25/26 feed export; the gap the feed shows is content depth (keywords, descriptions, highlights), not missing data.

One partner per channel

Google Shopping and Meta run off the same optimisation engine today — LIA is live in IE, giving a template to extend Click & Collect to other markets as the account grows.

Blockers get named, not absorbed
