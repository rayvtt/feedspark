# UI language — Ray's Vietnamese view (Sep 2026)

Ray's ask (15 Sep 2026): *"build completely a VI (Vietnamese) toggle for my view only."*

The FCC is ~20 pages of English chrome rendered by inline scripts; nothing is templated for
translation. So the toggle translates the **DOM in place** and restores it on the way back —
no page was rewritten, and no other signin ever sees the pill.

## Parts

| Part | File | Role |
|---|---|---|
| Engine | `docs/i18n_engine.js` (served at `/i18n/engine.js`) | Pure rules, UMD, node-tested: what to **skip** (URLs, emails, `g:` attribute keys, market codes, codes like `YMDCR15`, numbers, `[Client]` placeholders), how a string is **keyed** (whitespace-normalised, every number → `{n}` so one entry answers every count, numbers ride back in order), how a dictionary **answers** (exact → number-template → case-insensitive), and which tokens are **protected** (brand / client / platform / product names, `SKU`/`AM`-style acronyms — whole-word, plural-canon so `SKUs` may come back as `SKU`). |
| Seed | `docs/i18n/vi.json` (served at `/i18n/vi.json`) | ~1,800 hand-written entries covering every app page's chrome, sized from a Playwright extraction of the visible strings. Identity entries (`Google Shopping` → `Google Shopping`) are deliberate keep-as-is answers. |
| Widget | `docs/lang_widget.html` | The `#lang-tgl` EN/VI pill in the topbar. Walks every text node + `title` / `placeholder` / `aria-label` / `alt`, a MutationObserver keeps re-rendered content translated, `html[lang]` flips. Never touches input values, textareas, selects, `contenteditable`, the dossier's `data-ed` fields, code, the Templates copy bodies (the Copy button reads them) or the wordmark. Back to EN = exact originals restored off the live DOM (WeakMaps, nothing pins detached nodes). State: `localStorage fcc-lang`. |
| Worker | `cloudflare/feedspark-deck/src/worker.js` | Injects the widget **only for the real owner identity** (`realOwner` — never another signin, never under view-as). `/api/i18n` (owner-only): `GET` = the learned map, `POST {lang:'vi', strings}` = translate the misses via Tachyon with the house glossary, protected tokens enforced server-side (`i18nKeeps`), cached in **one KV key** `i18n:vi`. |

## Runtime lane

Strings the seed cannot answer (plan-task names, new copy) queue in the widget, go up in
batches of ≤80 (max 10 batches per page load, 700 ms debounce) and come back cached — every
later page load has them from `GET /api/i18n`. Without `ANTHROPIC_API_KEY` the route answers
`error:'no_key'`, the widget stops asking and the pill's tooltip says so; the seed still applies.

## QA

- `node tools/test_i18n.mjs` — engine rules, templating, protection, seed integrity, worker
  parity (`I18N_KEEP` ≡ engine `KEEP`), owner gating of the route and the injection, widget
  skip / restore rules. Wired into `qa_gate.sh`, `presync.sh` and `validate.yml`.
- Playwright sweep (session scratch, `qa_i18n.js`): every app page via `file://` with stubbed
  fetches — toggle on, numbers preserved, placeholders translated, values / contenteditable /
  data-ed untouched, learned-map merge, runtime batches, toggle off = byte-identical restore,
  no-key degrade. Live host checks are moot (Access login page), per DEPLOY_PROTOCOL.

## Adding language

Add entries to `docs/i18n/vi.json` (key = normalised English with numbers as `{n}`), keep
protected tokens verbatim, run the harness. A second language = another seed file + `lang`
value; the engine and widget are language-agnostic.
